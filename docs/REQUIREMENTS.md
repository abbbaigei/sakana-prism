# Sakana Prism · 配置需求

> 适用版本：0.4.27 及以后
> 运行形态：Salt Player for Windows（Steam appid 3009140）的工坊插件，随宿主进程一起运行

Sakana Prism 自身只是一个约 **360 KB** 的 `.spmod`，没有独立进程、不装服务、不写注册表。真正的门槛来自两件事：

1. **实时 FFT**：主分析 16384 点，外加低频专用 32768 点（两者都要每帧跑）
2. **实时绘制**：声谱图每帧约 2.3 万个三角形，频谱视图是 512 个频点 × 最多 160 根柱

所以下面的配置需求 = **宿主要求 + 这两件事的余量**。

---

## 一、速查表

| | 最低配置 | 推荐配置 | 理想配置 |
| --- | --- | --- | --- |
| 操作系统 | Windows 10 64 位 | Windows 11 22H2 64 位 | Windows 11 23H2 及以上 |
| CPU | 双核四线程，2.0 GHz（x86-64） | 四核八线程，3.0 GHz | 六核以上，3.5 GHz+ |
| 内存 | 4 GB（宿主 1 GB + 插件 0.2 GB + 系统余量） | 8 GB | 16 GB |
| 显卡 | 支持 OpenGL 2.0 / DirectX 9 的集成显卡 | OpenGL 3.3 / DirectX 11 的独显或较新核显 | 任意近五年独显 |
| 显存 | 共享内存即可（插件本身不建纹理） | 1 GB 以上 | 2 GB 以上 |
| 磁盘 | 10 MB 可用空间 | 20 MB | 20 MB |
| 屏幕 | 1280 × 720 | 1920 × 1080 | 2560 × 1440 及以上 |
| 音频 | 任意宿主支持的输出设备 | WASAPI 共享 / 独占均可 | —— |
| 可达帧率 | 30 fps（自动档可能锁 30） | 60 fps | 60 fps + 其它插件共存 |

> 低于「最低配置」不是不能装，而是**声谱图会掉到 20 fps 以下**、低频柱可能看着不跟手；此时请按第六节降级。

## 二、逐项说明

### 操作系统

- **Windows 10 64 位** 是宿主 Salt Player 的官方最低要求，插件继承该要求。
- 32 位系统**不支持**：宿主与插件都是 x86-64。
- 插件使用 Compose Multiplatform（Skia）绘制，依赖宿主已加载的 JVM 与图形栈，不额外安装运行库。

### CPU

| 用途 | 说明 |
| --- | --- |
| 主 FFT | 16384 点，每帧一次；60 fps 下约 60 次/秒 |
| 低频 FFT | 32768 点，独立线程，约 25 次/秒（40 ms 一次） |
| 频段聚合 | 512 个频点 → 最多 160 根柱，纯查表 + 取峰值 |
| 声场 PCM | 1024 帧窗口扫描，**仅声场视图可见时执行** |

- 最低档（双核 2.0 GHz）能跑，但建议把帧率固定在 **30**。
- 推荐档（四核 3.0 GHz 以上）可稳定 60 fps。
- 插件**不依赖 AVX**，SSE4.2 即可；老至 Ivy Bridge 级别的 CPU 也能运行。

### 内存

- 插件自身的固定开销很小：
  - 历史缓冲：91 行 × 160 频点 × 4 B ≈ **58 KB**
  - 频谱帧 / 声场缓冲：几十 KB 量级
- 但它是**宿主进程内的插件**，JVM 堆由宿主统一管理，实际占用会体现为宿主工作集上涨。
- 本机实测（7 个插件共存、声谱图打开、160 频段）：宿主工作集约 **800 MB**。
- 只装本插件时，建议给宿主留 **1 GB** 余量；4 GB 内存机器上同时开浏览器等程序会比较紧。

### 显卡 / 图形

- 插件用 Skia 直接画在宿主的 Compose 画布上，**不创建纹理、不开 FBO**（辉光是用描边叠层模拟的，没有离屏模糊）。
- 需要宿主能正常初始化 OpenGL；驱动过旧或远程桌面/虚拟显卡环境下会退化为软件渲染，此时 CPU 占用会明显上升、帧率下降。
- 集显（Intel UHD / AMD Vega 集显）足以应付 60 fps 的声谱图。
- 显存需求可以忽略；4K 屏下主要压力在填充率，建议把窗口控制在 1440p 以内。

### 磁盘

- `.spmod` 包 **359 KB**，解压后 **101 个文件 / 853 KB**。
- 建议预留 20 MB（含宿主可能保留的旧版本与工坊缓存）。

### 显示

- 1280 × 720 下频谱页仍可用，但右侧设置栏会挤，声谱图的时间/频率刻度会比较密。
- 1920 × 1080 是推荐分辨率，声谱图默认视角能完整显示刻度。
- 高 DPI（150% / 200%）下界面按比例放大，等效可用区域变小，建议 1080p 起步。

### 音频

- 插件不接管音频输出，只读取宿主的解码流（BASS）。
- WASAPI 共享/独占、DSD、SRC 设置都不影响插件，插件跟随宿主的采样率。
- 采样率越高（96 kHz / 192 kHz），FFT 的频率分辨率越高，CPU 开销基本不变。

## 三、插件的实测开销

以下为**实测值**（本机：Ryzen 9 7940HX / 32 线程 / 31.2 GB / Windows 11 Pro 26300，7 个插件共存）：

| 项 | 数值 |
| --- | --- |
| `.spmod` 包大小 | 359.4 KB |
| 安装后体积 | 852.7 KB / 101 个文件 |
| 历史缓冲 | 91 × 160 × 4 B ≈ 58 KB |
| 声谱图三角形数 | 90 × 127 × 2 ≈ 22,860 个 / 帧 |
| 宿主工作集（全部插件） | 约 801 MB |
| 宿主线程数（全部插件） | 183 |

以下为**估算值**（按 FFT 规模推算，未做隔离实测，标注出来避免误导）：

| 项 | 估算 |
| --- | --- |
| 主 FFT + 低频 FFT 合计 | 0.3 – 0.6 个逻辑核心（60 fps 时） |
| 插件自身常驻内存 | 30 – 60 MB |
| 失焦降帧后（15 fps） | 约前台的 1/4 |

## 四、不同视图的负载

插件从 0.4.22 起按「谁显示谁计算」调度，视图之间开销差别很大：

| 视图 | 计算 | 相对负载 |
| --- | --- | --- |
| 柱状 | 主 FFT + 峰值保持 | 低 |
| 曲线 | 主 FFT + 峰值保持 | 低 |
| 镜像 | 主 FFT | 最低（不算峰值） |
| 声谱图 | 主 FFT + 历史缓冲 + 2.3 万三角形 | **最高** |
| 声场 | 跳过主 FFT，只做 PCM 扫描 | 中 |

**结论**：卡顿优先怀疑声谱图；把视图切到「镜像」能立刻省下一大截。

## 五、帧率档位

| 档位 | 目标帧率 | 适用 |
| --- | --- | --- |
| 30 | 30 fps | 最低配置、笔记本省电、多插件共存 |
| 60 | 60 fps | 推荐配置 |
| 自动 | 30–165 fps，按实测帧率折中 | 默认；显示器刷新率越高上限越高 |

另有「非焦点时降低帧数」（默认开）：窗口失焦后分析线程与显示线程都降到 15 fps，占用约为前台的 1/4。

---

## 六、达不到配置时怎么降级

按收益从大到小：

1. **帧率切到 30** —— 直接减半计算量
2. **视图切到「镜像」或「柱状」** —— 声谱图是最大的开销项
3. **频段数从 160 降到 96 或 64** —— 聚合与绘制都变轻
4. **开启「非焦点时降低帧数」** —— 挂后台时几乎不耗电
5. **低频从 32k 切到 16k** —— 低频线程的 FFT 规模减半
6. 关闭其它工坊插件，逐个排查
